### 실제 운영에서 다른 점

| 연습장 | 실제 운영 |
|---|---|
| 한 터미널에서 다 함 | 인터넷 PC → 반입 매체 → 관리망 PC → infra01 / k8s-m1 |
| `cp` | `scp root@<infra01>`, `scp root@<k8s-m1>` |
| `sed` 로 태그 · 비밀값 넣기 | `vi` 로 직접 고침 (같은 내용) |
| `ai.lab.example`, `docker.io/lab/...`, `lab.io/role` | 운영 도메인, 기관 이미지 이름, 운영 라벨 (가이드 4 · 5장) |
| 업무 서버 1대 (node01) | 업무 서버 2대 — 파드가 하나씩 갈림 |
| 공통 DB 1개 (단순) | 운영 DB (복제 · 백업 포함) |

### 내 서비스로 옮길 때 — 가이드 7장 ① "앱 수정 확인"

- 화면: 빌드 base 와 라우터 basename 을 내 외부 경로로 (예: `/hub/`). API 는 상대경로만.
- 운영 접속 정보(DB · Redis · 외부 주소)는 전부 환경변수로. 소스에 비밀번호 · 개발 서버 주소 금지.
- 다른 서비스 호출은 `…svc.cluster.local` 내부 주소로.
- 인터넷 호출(지도 타일 · 외부 API · CDN)은 폐쇄망에서 안 됨 → 내부 대체 또는 끄기.
- 로그는 표준출력, 쓰기는 `/tmp` 만 — 2단계 ④처럼 `docker run --read-only --tmpfs /tmp` 로 미리 확인.
- 데모 · 게스트 로그인, 시험 계정 제거.

### 같은 연습장을 내 PC 에서

리눅스 또는 윈도우 WSL2(우분투) + 도커가 있으면:

```
git clone https://github.com/hongin81/gc-k8s-lab && cd gc-k8s-lab
sudo bash lab/setup.sh --mode kind
```{{copy}}

내 PC 연습장에는 **내 서비스 이미지**를 올려 보고 반입 전에 미리 확인할 수 있습니다.
